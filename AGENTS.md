- Reto 2.700 lives in separate `reto_*` tables keyed by event_id; reciprocal connections are computed in the DB, never stored or trusted from the browser — keeps the existing likes/matches/meetings untouched.
- Closing the Reto freezes results into `reto_snapshots`/`reto_snapshot_pairs` and `reto_scoreboard`/`reto_connection_count` read the snapshot while closed — prizes come from a stable, auditable copy; all admin writes go through `reto_admin_*` SECURITY DEFINER functions that check super_admin.
- Reto 2.700 end-to-end checks live in `scripts/reto-2700/simulacion.ts` (run with bun); it only touches the hidden TEST event, verifies real data is unchanged and leaves the test event clean — rerun it after any `reto_*` SQL change.

- Open chat is person-to-person in `chat_dm` (user_a < user_b); sending is gated in RLS by `chat_dm_allowed` (both active empresa/solución profiles) — permission lives in the DB, not the UI. Old `chat_messages` is kept unused.
- Meeting proposals come from the pure engine in `src/lib/meeting-generator.ts` (tested), fed by event rules + availability; nothing is written until the admin approves the draft — keeps scheduling rules testable and reversible.
- Event membership = an account with at least one non-cancelled `event_registrations` row; every panel (admin and participant) scopes accounts, likes, matches, meetings and notices through `src/lib/event-scope.server.ts` (`getEventScope`, `pickCurrentEvent`) — keeps each event fully independent with one shared definition.
- List filtering and alphabetical ordering live in pure, vitest-covered helpers under `src/lib` (e.g. `registration-list.ts`) that routes call; routes keep only state and markup — keeps who-is-shown-and-in-what-order checkable without a browser session.
- 1to1 meetings are hidden from participants until `events.meetings_published` is true; enforced in the `meetings_1to1` read policy and the notify trigger via `meetings_visible()` — admins can edit drafts safely without leaking or notifying.
